# Science dependency-set plan preparation

`scripts/experiments/gemma4-purpose/prepare_science_dependency_plans.py` binds a prospective method policy to completed native and sampled-matrix correct-logprob/margin observations of one saved parent. It writes seven B–H plans and a roster, and never invokes a solver or a model. A separately verified full carried edit is the A arm.

The command requires `--repo`, `--observation`, `--output`, `--parent-sha`, `--review`, `--review-sha`, `--method`, and `--method-sha`. The observation directory contains the completed owner plan, restoration receipt, output hashes, postchecks, and independent baseline comparison. The review must identify the requested tool-disabled model and publicly review all A–H labels. All paths are explicit; the output must be fresh.

The pinned method supplies eligible blocks/families and primary/secondary purposes. Positive correct-LL targets are the smaller of the declared multiplier times the eligible cost-dual norm and one tenth of current-parent LL headroom. Margin targets use their own derivative units without that LL ceiling. All 84 ordered objective rows remain present. The current recipe uses relative cost with floor 1e-6, a 0.025/1e-6 continuous coordinate box, and 16 existing BF16 correction rounds. The later realized weighted-norm cap is a separate owner postcheck; this builder does not claim feasibility.

B/E/G can exclude the final native norm and every native tensor in the highest observed layer by exact tensor name. Full native observation validation remains mandatory, and the same eligibility is applied before deriving targets and before solving. H normalizes each block's cost by its RMS dual sensitivity over the twelve scientific correct-LL folds. These are local parameter metrics, not function-space or ability guarantees. A mixed eligible scope may realize changes in only one block.

The portable file preserves the executed preparation algorithm. Its additional boundary check rejects output overlap with the checkpoint, observation/collection directories, and pinned method/review inputs before creating anything. Formatting and removal of two unused inherited local names do not alter the calculation. The original runtime source and actual plans remain pinned. Its existing tiny builder E2E also exercises the science variant: earlier native eligibility survives last-layer exclusion, LL headroom and margin units differ, block normalization is derived from the fixture, the checkpoint is untouched, and a foreign output is preserved. It runs no optimizer.

`summarize_dependency_set_proposals.py` accepts either the original eight-set embedded policy or a SHA-pinned prospective method. It reconstructs exact selected BF16 deltas from saved source arrays, rejects ineligible native/family edits, retains analytical misses, and reports raw, unscaled-relative, declared-weighted norms and post-rounding continuous-box excess. Policy files participate in input SHA/stat continuity. An actual norm cap is not a zero-loss accuracy gate.

See [the AD science experiment](experiments/2026-11-07-ad-science-dependency-sets.md) for the frozen method, completed CPU proposals, and the distinction between predicted and measured behavior.
