## Incumbent and observed model are separate identities

The plan pins the unchanged `working-incumbent.json` under `parent`.
Its separate `observed_parent` contains the saved checkpoint path, whole-file
tree, freeze, service and explicit mode:

- `accepted`: the observed path/tree must equal the current incumbent.
- `provisional`: a root-selected saved finalist may be observed during retention
  evaluation while the current incumbent remains unchanged. This is an
  observation of that exact finalist, not adoption.

All four collector commands must name the same observed checkpoint, attestation
and case file. The attestation must bind that exact path/tree and freeze; the
existing full-file proof and current file stamps are checked before and after
the collection. A new physical payload hash pass is not added by this owner.

Future edits may use provisional observations only if that exact model becomes
the accepted parent. At edit creation, bind the then-current incumbent again.
Old AD absolute `set_values`, or gradients from another checkpoint, must not be
relabelled as increments on a newly accepted AN/AR. No candidate or checkpoint
is written by the observer.
