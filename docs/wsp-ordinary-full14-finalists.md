# Ordinary full14 finalist comparison

[Owner recipe](experiments/scripts/launch-ad-finalists-full14.py) prepares a fresh accepted-AD control and one or two selected saved AN/AR finalists on the fixed tier10/dev cohort. It reuses the ordinary TP2 deployment, command, source attestation, numeric observation and counter contracts from the saved-finalist dev90 owner.

This recipe is prepared and independently reviewed. It has not executed a full14 comparison. Final candidate selection, serving snapshots, completed ordinary-dev90 evidence, and root decision remain unbound.

## Fixed protocol

- AD remains on replica1; selected finalists use replicas0 and3. The owner does not deploy, stop or restore services.
- Every selected arm receives the same778 items over all14 areas, chat concurrency32, logprob concurrency8 and agent concurrency1. Native reasoning, sampler, caps and archived5e3 source remain unchanged.
- TP2 serving is retained. This is separate from the unexecuted TP2×DP2 proposal.
- Each arm gets its own numeric RequestRecorder directory with the same policy. Completed HTTP attempts, logical calls and retries are separate from judged items and agent steps.
- The wrapper runs from the results directory. Early actual-OCI capture requires the deepest covering mount to be a writable bind to that same host path, preventing the demonstrated missing-output-mount failure.
- Actual image/config/rootfs, commands, source82 files/resources and counters are captured before runner auto-removal. The full14 source-count/environment reference is the prior completed ordinary AD plan; it is a protocol reference, not a substitute for the new control run.

## Preparation and execution boundary

The recipe accepts an explicit JSON plan and its SHA256. An unbound plan has an inert default preview: no Docker, HTTP, model or benchmark actions. A bound preview performs the existing metadata/readiness checks but does not launch.

Execution additionally requires a root decision pinned to the exact plan/runtime/current-parent and completed saved-dev90 closure. The decision lists the selected one or two finalists. Each receives one fresh run; there is no automatic retry, follow-up run or adoption.

Example syntax (paths and digest must be bound):

    python launch-ad-finalists-full14.py --plan PLAN.json --plan-sha256 SHA256
    python launch-ad-finalists-full14.py --plan PLAN.json --plan-sha256 SHA256 --apply

Private HF authentication is inherited in the environment and is not written to receipts. The task-specific helper paths remain explicit: this file is a reproducible owner recipe, not a general deployment framework.

After all runs finish, use the existing safe numerical exporter for fresh matched all14/source contrasts, usage, partial scores and missingness. Purpose tradeoffs are reported without adding an all-area-no-loss or significance gate. Root owns the later adoption decision.
