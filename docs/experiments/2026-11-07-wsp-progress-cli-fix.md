# Explicit target binding for WSP progress monitoring

An operator invoked the old progress script with --help to inspect its interface. It had no argument parser and ignored argv, so it queried read-only metrics and appended one snapshot to its hardcoded, already-completed AV run. The accidental record is AV progress.jsonl line 29, epoch 1794059547.4666736. The line remains unchanged. This was monitoring of an existing result, not another model generation, scoring run, baseline evaluation, or new trial; the canonical scores were not changed. The exact appended record, original source and [incident receipt](records/2026-11-07-wsp-progress-cli-fix/incident.json) are retained.

The minimal fix requires --analysis-root and --run-root. It matches the owner-start receipt's exact SHA to an existing plan in the specified analysis directory, then verifies the plan's result location/run ID/capture identity against run.json's observation, label, tier and split. A mismatched pair fails before metrics requests or output. No default evaluation directory exists. The original aggregation body was moved unchanged into collect(analysis_root, run_root); an AST comparison proves it is identical. The owner, scoring implementation and runtime conditions were not changed.

Argparse handles help before file reads, metrics or appends. Three focused tests cover help/missing arguments without I/O, valid binding and wrong analysis/run pairs, and tampered metadata/plan. All passed, as did Ruff and whitespace checks. Actual --help completed in 0.071 seconds, and the old AV progress file remained byte-for-byte unchanged throughout validation. No new full test suite, model call, monitor collection, or service operation was run.

Usage is in the [recipe README](scripts/README.md#explicit-wsp-progress-snapshot). The corrected source SHA is b203aada2141a2e2aa9cfd65434715eb0f8e9923c66864ee0708a34110012913.
