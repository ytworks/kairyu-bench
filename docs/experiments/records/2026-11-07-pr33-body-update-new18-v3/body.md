WSP weight experiments need reproducible links between stored weights, runtime activations, numerical proposals and official outcomes. This PR adds inspection/edit/verification tools and bounded experiment owners, with exact parent provenance, lossless trial retention and explicit CPU/GPU validation limits. Official scorers, manifest selections and default inference behavior remain unchanged.

## Tools

- CPU checkpoint statistics, sampled spectra/alignment, dtype-aware differences, scalar/vector/sparse-matrix/full-unit edits, shard reuse and complete saved-byte verification.
- Runtime activation capture with question/call/rank/token-position joins, dropped/unmatched/writer-state accounting, comparison and HTML inspection.
- Gemma sensitivity, coupled-objective proposals and fixed finite replay with BF16 readback and exact restoration. Proxies never become WSP scores; sampled norms and full-model denominators remain distinct.
- Explicit service owners that preserve unrelated services and restore exact owned containers, plus a host-wrapper option to reuse a full local Docker image ID without rebuilding or pulling. Mounted runtime caches and serving conditions still require separate attestation.

- Native public-answer generation with retained HTTP failures, plus isolated offline scientific/helper diagnostics that bind complete response envelopes and preserve missing/error outcomes.

[Tool inventory and guides](https://github.com/ytworks/kairyu-bench/blob/codex/weight-observation-tools/docs/wsp-tool-inventory.md) contain the executable entry points and validation boundaries.
